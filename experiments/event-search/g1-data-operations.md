# G1-03 데이터·운영 조사 v2

확인일: 2026-11-17 (Asia/Seoul). 입력: [G0 기록](g0-pilot.md)과 사용자 설명. **출발 사업 가설은 여러 출처에 흩어진 다양한 이벤트의 통합 검색이다. 에이전트 팀에는 근거에 따라 실험 범위를 좁히거나 방향을 바꿀 재량이 있다.** 서울 주말 행사 실험과 사업 전체의 축소를 구별한다. 브랜드 프로모션·할인·증정·응모·팝업·체험 등은 검증을 위한 분류 제안이다. 먼저 조사한 문화행사 자료는 하위 범주 및 제한된 검색 서비스와의 비교 자료로 보존한다.

상태: 공식 웹페이지·문서 조사 완료. API 키 발급·API 호출·30항목 수집·7일 추적은 실행하지 않았다. 아래 출처의 존재는 실제로 확인했지만, 필요한 항목 수·정확도·재사용 적합성을 확보했다는 뜻은 아니다.

## 공식 출처 조사

### S1 서울 열린데이터광장 — 서울시 문화행사 정보

[OA-15486 상세·API 안내](https://data.seoul.go.kr/dataList/OA-15486/S/1/datasetView.do?tab=A)에서 Sheet/Open API 제공과 서울문화포털이 원천시스템임을 확인했다. 문서상 `culturalEventInfo` API는 인증키가 필요하고 JSON/XML 등의 형식을 지원한다. 제목·분류·자치구·일정·장소·대상·요금·홈페이지·좌표·행사시간 필드를 안내한다. 갱신주기는 매일 1회, 열람 당시 갱신일은 2026-11-17이었다. 이는 개별 행사의 변경 반영 지연을 보장하지 않는다.

페이지의 이용허락 표시는 공공누리 1유형이며 출처표시를 요구한다. 실제 배포 필드와 이미지별 조건은 수집 전 재확인한다. 파일 영역에는 파일이 없다고 표시되어 다운로드 가능성을 검증하지 못했다. 검색 색인의 과거 갱신일보다 이번 직접 열람 값을 우선했다.

[OA-23041](https://data.seoul.go.kr/dataList/OA-23041/S/1/datasetView.do)도 같은 문화행사 제목과 서울문화포털 원천을 가진다. 매일 1회·공공누리 1유형 표시를 확인했다. 두 ID의 대체·병행 관계는 미확인이다. **두 개의 독립 공급원으로 세지 않는다.** 키 없이 실제 반환 스키마·누락률·운영 상태를 검증하지 않았다.

### S2 한국관광공사 — TourAPI 국문 관광정보

[공공데이터포털 공식 명세](https://www.data.go.kr/data/15101578/openapi.do)에서 REST, JSON/XML, `KorService2`, 필수 `serviceKey`, 행사정보 제공을 확인했다. 조회 문서는 관광 유형·법정동 지역·수정일 등의 선택 조건을 안내한다. 화면에 확인된 요청 필드와 실제 행사 응답 스키마를 혼동하지 않으며, 행사별 시작·종료·요금·취소 필드의 실제 충족 여부는 미확인이다.

갱신주기는 실시간, 비용은 무료, 이용허락범위는 제한 없음으로 표시되어 있다. 다만 같은 안내에 이미지 공공누리 1·3유형과 이용 제한이 별도로 기재되어 있으므로 모든 이미지를 자유 사용으로 처리하지 않는다. 이번 실험은 이미지 복제 없이 필요한 사실 필드·원문 참조 중심으로 설계한다. 공식 메타데이터의 실시간 표시는 취소 반영 SLA나 해당 주말의 서울 행사 확보를 입증하지 않는다. 활용신청·키 발급·실호출은 하지 않았다.

### S3 서울관광재단 — Visit Seoul 행사·API

[공식 행사 목록](https://korean.visitseoul.net/eventsx)에서 기간 검색과 진행 상태·행사 제목·날짜·상세 링크를 확인했다. 공개 웹 열람에는 키가 필요하지 않았다. [상세 페이지 표본](https://korean.visitseoul.net/eventsx/2026MyeongdongSquare-MissionFesta/KOPfq5ffd)에는 제작·수정일, 장소, 이용시간·요금, 예약·웹사이트 링크가 있었다. 표본 하나의 존재로 전체 필드 충족률을 추정하지 않는다. 정기 갱신주기는 확인하지 못했다.

[API 센터](https://api.visitseoul.net/main/home)도 존재한다. 과거 오픈 예정 팝업과 오픈 공지가 함께 남아 있어 화면만으로 현재 발급 가능 상태를 단정하지 않는다. FAQ는 로그인으로 이동했고, API 필드 명세·호출 한도·갱신 계약은 확인하지 못했다.

[서비스 이용약관](https://api.visitseoul.net/term/view?lang=ko)은 키 발급 신청·승인된 용도 범위, 활용 표시·원출처 명시, 사전 승인 없는 데이터 유료 제공 제한을 규정한다. 웹 공개열람을 API 이용 승인이나 본문·이미지 재배포 허가로 간주하지 않는다. 유료 서비스와의 적합성은 구체적인 제공 방식에 따라 추가 확인해야 하며 여기서 법률 판단을 내리지 않는다.

### S4 보조 확인 경로 — 서울문화포털·펀서울

[서울문화포털](https://culture.seoul.go.kr)과 문화행사 목록 URL은 이번 열람 도구에서 timeout으로 실패했다. 사이트 전체 장애라고 판단하지 않는다. S1 공식 문서로 원천 관계만 확인했다.

[펀서울 공식 계절별 축제](https://festival.seoul.go.kr/festival/seasonal/list.do)는 열람에 성공했다. 제목·구·기간·장소·예정 표시가 보이고 하단에 서울문화포털·서울시 문화정책과가 표시된다. 공개 열람에는 키가 필요하지 않았지만 API·갱신주기·재사용 조건은 확인하지 못했다. 서울문화포털과 조직·콘텐츠가 연결된 경로이므로 공급 독립성이 확인된 것으로 세지 않는다.

### S5 스타벅스 코리아 — 브랜드 이벤트

[공식 이벤트 목록](https://www.starbucks.co.kr/whats_new/campaign_list.do)을 직접 열람해 전체·카드·리워드·온라인 분류와 진행/종료 구분을 확인했다. 로그인·키 없이 메뉴는 열렸지만 이번 텍스트 추출에는 개별 카드가 비어 있었다. [공식 상세 URL](https://www.starbucks.co.kr/whats_new/campaign_view.do?pro_seq=3593)의 검색 색인에는 카드·앱 결제 조건, 할인·적립·증정 관련 이벤트가 노출됐으나 직접 열람에서는 해당 조건 본문을 재현하지 못했다. 따라서 이를 현재 참여 가능 혜택이나 확정 레코드로 채택하지 않는다.

범주 후보는 구매·회원·결제 방식에 따른 혜택이며, 문화행사의 장소·일정만으로 설명되지 않는다. 공개 API, 갱신주기, 본문·이미지의 수집 및 재배포 허용 조건은 이번 조사에서 확인하지 못했다. 공개 목록 존재와 재사용 가능한 공급 확보는 별개다. 다음 수동 확인에서는 상세 이미지·조건 원문을 사람이 대조하되 별도 복제 허용을 확인하기 전에는 대량 저장·공개 재배포하지 않는다.

### S6 삼성스토어·삼성닷컴 — 구매 프로모션·리뷰·퀴즈

[삼성스토어 공식 이벤트 목록](https://www.samsungstore.com/event/list.sesc?menu=w105)을 직접 열람했다. 제목·시작/종료일과 구매혜택·리뷰·구독·제휴 프로모션 관련 항목이 보인다. 진행/종료/당첨자 발표 필터가 있다. 페이지에 종료된 날짜 항목도 함께 있으므로 제목 노출만으로 진행 상태를 정하지 않는다. 로그인·키 없이 목록을 열었지만 공개 API와 갱신주기는 미확인이다. 하단에 무단 전재·복사·배포 제한 안내가 있어 콘텐츠 재사용 허가를 확보한 공급원으로 간주하지 않는다.

[삼성닷컴 이벤트 개인정보처리방침 목록](https://www.samsung.com/sec/info/privacy/02/)에서도 퀴즈·리뷰·구매자 초청 등 제목과 기간을 확인했다. 이는 이벤트 발견의 보조 경로이며 전체 참가 조건·당첨 방식·수령 조건을 제공한다고 판단하지 않는다. 같은 삼성 계열 행사·동일 캠페인을 별도 독립 공급으로 중복 계수하지 않는다. 행사별 응모 동의 절차를 목록 검색 서비스가 대신 수행하지 않는다.

보조 실패 기록: GS25의 기존 공식 이벤트 목록 주소는 [현재 브랜드 페이지](https://www.gsretail.com/brand/gs25)로 이동했고 이번 도구에는 JavaScript 필요 안내만 반환됐다. 공개 이벤트 공급이 없다는 결론은 내리지 않으며 이번 확인 성공 출처로 세지 않는다.

## 범주별 조건 차이 — 레코드 설계 가설

| --- | --- | --- |
| 문화행사·체험 | 회차·예약·장소·대상·가격 | 공식 포털과 일부 상세 확인; 공급 수집 미실행 |
| 할인·적립 | 결제수단·최소금액·한도·회원·중복 적용·지급일 | 브랜드 목록 존재 확인; 개별 조건 전수 미확인 |
| 구매 증정 | 대상 상품·구매 채널·수령 방식·재고·소진 종료 | 후보 범주; 유효 표본 확보 미완료 |
| 응모·퀴즈·리뷰 | 응모 행위·자격·당첨 방식·발표·수령 조건 | 삼성 공식 보조 목록에서 유형 확인; 상세 미검증 |
| 팝업·브랜드 체험 | 장소·회차·예약·현장 참여·혜택 조건 | 추가 공식 출처 확보 필요 |

## 공급 독립성과 이번 판단

S1의 두 데이터셋과 서울문화포털은 동일 원천 계열이다. S4 역시 별도 독립 공급으로 가산하지 않는다. S2·S3는 제공기관이 다른 후보지만, 동일 행사나 주최자 자료가 중복될 수 있다. 따라서 공식 경로 3개 이상 확인과 독립 원천 3개 확보를 구분한다. 현재는 **재사용 조건을 확인한 독립 원천 3개·유효 항목 30개 확보 미완료**다.

브랜드 출처 S5·S6를 추가했지만 재사용 허가나 API를 확보하지 않았다. 문화행사 데이터만 확보해 전체 이벤트 공급 성공으로 보고하지 않는다. 자료가 존재한다는 이유로 범용 수집기를 먼저 만들지 않으며, 여러 범주의 공급·조건 표준화·갱신 가능성을 수동으로 비교한다. 이것은 운영 제안이며 공급 계약 체결 결과가 아니다.

## 표준 레코드 계약 제안

| 그룹 | 필드·규칙 |
| --- | --- |
| 식별·이력 | `record_id`, `revision`, `source_family`, `source_id` 또는 원문 URL, `source_url`, `organizer_url`, `duplicate_group_id` |
| 행사 | `title`, `category`, `district`, `venue`, `address`, 선택 좌표 |
| 일정 | `start_date`, `end_date`, `session_schedule`, `timezone=Asia/Seoul`, `schedule_note`; 날짜 범위만으로 매일·매주말 운영한다고 추정하지 않음 |
| 참여 조건 | `eligibility`, `price_text`, 선택 구조화 금액, `booking_requirement`, `booking_url`; 미기재와 무료·예약 불필요를 구별 |
| 혜택·응모 | `benefit_type`, `benefit_description`, `minimum_purchase`, `payment_constraints`, `membership_constraints`, `participation_action`, `entry_deadline`, `selection_method`, `announcement_date`, `redemption_terms`, `stock_end_condition`; 해당 없음과 미확인 구별 |
| 적용 채널 | `channel=online/offline/both/unknown`, `participating_stores`, `region_scope`; 온라인 이벤트에 임의의 서울 주소를 요구하지 않음 |
| 상태 | `status=scheduled/ongoing/ended/cancelled/unknown`, `status_evidence_url`; 페이지 삭제는 취소 확정으로 처리하지 않음 |
| 출처·권한 | `rights_status=confirmed/pending/excluded`, `rights_evidence_url`, `rights_checked_at`, `attribution`; 필요 조건 미확인 자료는 공개 목록에 배포하지 않음 |
| 확인 | `first_seen_at`, `source_modified_at` 또는 null, `last_checked_at`, `last_success_at`, `reviewer`, `check_result`, `field_evidence`, `collection_minutes`, `review_minutes` |

값이 없으면 null과 이유를 보존한다. 모델이 추정한 주소·무료 여부·참여 조건을 확정 필드로 채우지 않는다. 제목 유사성만으로 합치지 않고 기간·장소·주최자를 함께 비교한다. 서로 다른 회차와 사전·본행사를 구별하고, 중복 레코드를 합쳐도 출처별 이력은 남긴다. 원본 상세 본문·이미지의 대량 저장은 이 계약에 포함하지 않는다.

## 7일·30항목 수동 검증 계획 — 미실행

아래는 제안한 탐색 기준이다. 통계적 시장 입증이나 운영 SLA가 아니다. 시작 전에 기간·범위·인력·현금·모델 한도를 재무안과 맞춰 동결한다.

1. D0 준비: 조사 기준일과 적용 기간을 고정하고 출처별 접근·이용 조건을 기록한다. 목표 30개를 할인·적립 6, 구매 증정 6, 응모·퀴즈·리뷰 6, 팝업·브랜드 체험 6, 문화행사·체험 6으로 층화한다. 이는 제안 분류이며 각 이벤트는 주범주 하나에만 배정하고 부태그는 별도 보존한다. 원천 계열별 후보 수, 제외 이유, 중복 제거 후 수를 기록한다. 부족한 브랜드 범주를 문화행사로 채워 목표 달성으로 보고하지 않는다.
2. D1 기준선: 고유 이벤트 30개를 고정 코호트로 등록한다. 기간·혜택·참여 조건·적용 채널 및 해당 시 장소/회차를 원문으로 대조한다. 오류나 부족 항목도 분모에서 빼지 않는다. 기록 조사와 공개 배포를 구분해 재사용 미확인 자료는 공개 코호트로 전환하지 않는다.
3. D2~D7: 같은 시각에 매일 전체 코호트를 확인한다. D1~D7 총 210건의 레코드-일 점검이 계획 분모다. 접근 실패·누락 점검도 실패로 남긴다. 취소·종료 항목은 표시를 변경하되 코호트에서 제거하지 않는다.
4. 변경 점검: 날짜·회차·장소·가격·대상·예약·취소를 비교해 이전값/새값/근거/발견시각/반영시각을 기록한다. 발견한 중요 변경은 다음 공개·추천 전에 반영한다. 실제 원문 변경시각이 없으면 발견 후 반영시간만 측정하고 원문 변경부터의 지연을 주장하지 않는다.
5. 장애 점검: 접근 실패는 `unknown`으로 표시하고 마지막 성공 시각을 보존한다. 취소 근거가 없는데 페이지가 사라졌다고 취소 확정하지 않는다. 예정일 경과와 실제 종료 여부도 구별한다.
6. D7 보고: 확보량·원천 다양성·누락률·변경 발견 건수·반영시간·오류·총 작업시간·상한 초과 여부를 함께 보고한다. 변경 0건이면 변경 대응 검증은 미확인이다. 별도 합성 취소 시나리오를 추가해도 실제 운영 성과에 합산하지 않는다.

### 90% 기준의 분모

필수 8그룹은 제목·주체, 유효기간/종료조건, 혜택 또는 행사 내용, 적용 채널/지역, 참여 자격·행동·비용 조건, 수령/응모/예약 조건, 원문 URL, 확인시각이다. 범주별 세부 조건이 해당 그룹에 충족되어야 한다. 알려진 값 또는 원문에 명시된 해당 없음만 충족으로 센다. 단순 `unknown`·미기재는 충족이 아니다.

- 레코드 완전성: **8항목을 모두 충족한 고유 행사 수 / 고정 30개**. 목표는 최소 27/30이다. 필드별 충족 합계를 240으로 나눈 별도 지표로 이 기준을 대체하지 않는다.
- 추적 수행률: **완료된 일별 점검 수 / 210**. 90% 기준과 별개로 전수 점검을 목표로 하며, 빠진 점검과 사유를 공개한다.
- 30개 미확보: 실제 확보 수 N과 완전성 `충족/N`을 보조 보고하되 **30항목 목표 미달**로 판정한다. 표본을 줄여 90%만 통과했다고 보고하지 않는다.
- 범주 커버리지: 각 층 확보 수/6, 완전 레코드 수/6, 전체 5개 층 중 확보된 층 수를 따로 보고한다. 독립 공급 지표는 원천 계열 수·주최자 수·계열별 집중도로 보고하며 범주 수로 대체하지 않는다. 전체 27/30만으로 특정 범주의 실패를 숨기지 않는다.
- 원문과 틀린 일정·장소·가격 또는 알려진 취소의 공개 누락은 중대 오류로 별도 계수한다. 완전성 90%를 달성해도 이 오류를 허용한다는 뜻은 아니다.

## 시간·비용 추정과 재심 조건

인력시간의 초기 가정이며 실측값이 아니다. 여러 브랜드의 이미지·동적 페이지·조건 확인을 반영해 출처·조건 확인 3~5시간, 기준선 30건×6~12분=3~6시간, D2~D7 확인 180건×1~3분=3~9시간, 중복·변경 처리·보고 2~3시간으로 합계 **11~23시간**을 제안한다. 기존 문화행사만의 7.5~15시간 추정은 폐기한다. 접속 대기와 실제 작업시간을 구분해 타이머로 기록한다. 신규 수집 분/건, 반복 점검 분/건, 변경 처리 분/건, 총시간을 각각 보고한다.

원가 산식은 `실제 인력시간×승인된 환산단가 + 모델 사용량×확인된 단가 + 데이터·인프라 실지출`이다. 단가·모델 비용은 아직 unknown이며 이 문서는 지출 승인이나 무료 총사업비 주장이 아니다. 기존 브라우저·표로 수동 점검하는 안에는 신규 서버가 필수는 아니다.

제안 상한은 데이터 업무 총 23시간이다. 반복 점검 평균이 3분/건을 초과하거나 총한도 소진이 예상되면 샘플 수·접근 방식·중단을 재심한다. 팀은 근거를 남겨 범위를 변경할 수 있으나, 제한된 실험의 성공을 사업 전체 통합검색의 성공으로 확대 해석하지 않는다. 이 기준은 수익성을 입증하지 않으며 재무안과 통합 후 확정한다.

활용 조건이 불명확하면 해당 출처를 배포 대상에서 제외하고 내부 조사 참조로만 둔다. 필요한 공급이 부족하면 허용된 단일 출처로 더 좁은 연구를 할지 재심하고 3원천 성공으로 보고하지 않는다. 30건이 부족하면 기간 확장 또는 범주 변경을 별도 결정으로 남긴다. 자동 수집으로 부족한 권한·품질 근거를 대체하지 않는다. 고객 검증이 통과하더라도 공급·유지 비용이 실패하면 제품 개발 투자를 보류한다.

## 최종 교차 검토 — A: 여러 범주의 작은 공급 검증 추천

현재 A(다범주 작은 검증), B(특정 범주 진입), C(서울 문화행사 한정) 중 **A를 추천**한다. 공공 문화행사에는 구조화된 공급 안내가 있지만 브랜드 이벤트는 동적 페이지·이미지·참여 조건·재사용 조건의 미확인이 남아 있다. 이 차이를 확인하지 않고 C로 출발하면 쉬운 공급 경로만 시험하고 통합검색의 핵심 난점을 놓칠 수 있다. 반대로 B를 고를 만큼 범주별 고객 가치·유지 비용을 아직 비교하지 못했다.

실행은 5개 층에서 각 2개씩, **10개 후보의 접근·조건 파악을 먼저 시도하는 사전 단계**를 제안한다. 별도 추가 표본이 아니라 이후 30개 코호트에 포함할 후보이며, 4시간을 제안 상한으로 두고 전체 23시간 안에 포함한다. 이는 아직 실행하지 않은 제안이다. 막힌 범주도 실패 이유를 기록하고, 재사용·참여 조건을 확인할 수 있는 범주와 건당 작업시간을 비교한 뒤 30개·7일 시험 또는 B/C 진입을 재심한다.

C는 승인된 자료로 운영 절차를 시험하는 제한된 실험으로는 가능하다. 다만 실제 수요와 여러 출처 통합의 추가 가치를 검증하기 전에는 사업 전체를 서울 문화행사 서비스로 전환했다는 결론을 내릴 근거가 부족하다. 추천 A는 영구적인 범위 유지 의무가 아니며 다음 증거에 따라 B·C 또는 중단으로 변경할 수 있다.
