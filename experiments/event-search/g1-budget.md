# G1 단계별 실험 자원·예산안

작성일: 2026-11-17. 담당: 재무·투자. 입력: [G0 심의](g0-pilot.md)와 이후 사용자의 사업 의도·팀 재량 확인. 상태: 수정 제안안. 실행 실적이나 지출 승인서가 아니며, 고객·출처 확보와 단가는 미확인이다.

사업 가설은 다양한 브랜드 프로모션·할인·응모·팝업·체험 등의 이벤트를 한 번에 탐색하는 서비스다. 사용자는 좁은 범위도 에이전트의 근거 있는 결정이라면 허용한다고 확인했다. 다범주 유지는 강제 조건이 아니며, 아래 다범주 소규모 검증은 재무 담당의 추천안이다. 특정 진입 범주로 한정하는 실험과 사업 전체를 그 범주로 전환하는 결정은 구분한다. 조사 전 개발 투자는 보류하고, 이번에는 통합 탐색 가치와 공급·운영 비용을 검증할 자원을 편성한다. 아래 시간·횟수·표본은 실험을 제한하기 위한 제안값이며 생산성 추정이나 시장성의 증거가 아니다. 이 문서는 금융상품·투자 권유가 아닌 프로젝트 자원 계획이다.

## 범위 대안과 재무 추천

| 대안 | 비용 측면의 장점 | 판단 한계 |
| --- | --- | --- |
| A: 여러 범주의 소규모 검증 | 개발 전에 범주별 데이터 유지 비용을 비교해 후속 투자 대상을 고를 수 있음 | 분류·이용 조건 검토가 늘고 표본이 분산됨. 고객 수요는 미확인 |
| B: 특정 진입 범주 | 규칙·과업을 집중해 조사 시간을 줄일 가능성 | 선택할 범주에 관한 수요 근거가 아직 없어 성급한 선택 위험 |
| C: 서울 문화행사만 | 기존 검토 자료를 재사용할 가능성 | 자료 접근 편의와 고객 가치를 혼동할 위험. 다른 이벤트로 일반화 불가 |

재무 추천은 **A의 제한된 탐색 후 B를 선택하는 순서**다. A가 성공할 것이라는 판단이 아니라, 확인된 수요가 없는 상태에서 진입 범주를 고르기 위한 비교 비용을 제한하자는 제안이다. 아래 기준안의 총량·시간 한도 안에서만 수행한다. 팀이 근거를 추가해 B 또는 C를 택하면 입력 버전·판단 근거·검증 가능한 주장·예산 배분을 수정할 수 있다. 좁은 실험 결과만으로 사업 전체 피벗을 승인하지 않는다.

## 비용 장부의 분리

| 장부 | 산식 | 현재 상태 |
| --- | --- | --- |
| 인력 환산 | `Σ(사람의 실제 작업시간 × 담당별 시간당 환산단가)` | 시간은 작업별 기록, 환산단가 `unknown`. 에이전트 실행시간을 사람의 노동시간으로 간주하지 않음 |
| 외부 신규 현금 | `모집 사례비 + 유료 데이터 + 신규 인프라 + 광고 + 외주 + 기타 구매` | 이번 조사 제안의 한도 **KRW 0**. 각 항목 신규 구매 없음 |
| 모델 사용 | `Σ(모델·입력/출력/캐시 종류별 사용량 × 해당 단가)` | 사용량·단가·구독 포함 여부 모두 확인 전 `unknown`. 현금 장부와 중복 합산하지 않음 |
| 기존 자원 배분 | 기존 구독·장비·네트워크 등 중 이 실험에 귀속할 부분 | 배분 방식 및 금액 `unknown`. 무료라고 가정하지 않음 |

**외부 신규 지출 0원은 전체 실제 비용 0원을 뜻하지 않는다.** 현재 협업 모델 실행 비용도 미계측이다. 기존 도구 사용이 추가 결제 없이 가능한지 확인되지 않으면 추가 유료 실행을 계약하거나 확장하지 않는다. 자원 한도는 새 구매 없이 가능한 업무를 선택하기 위한 기준이다.

## 세 가지 편성안

각 안의 한도는 해당 단계 단독 한도이며 누적 한도가 아니다. 다음 단계로 넘어갈 때 이전 단계의 실제 사용을 별도 합산한다. 같은 작업을 여러 역할로 나누어 한도를 늘리지 않는다.

| 구분 | 최소안: 조사 설계 | 기준안: 수동 검증 | 확대안: 검증 후 제품 실험 |
| --- | --- | --- | --- |
| 산출물 | 여러 이벤트 범주의 고객 과업·모집·공급 검증 계획, 기록 양식, 재심 자료 | 최대 8명 고객 과업, 여러 이벤트 범주를 포함한 최대 30항목·3출처의 7일 수동 점검, 최대 14일 재요청 관찰 | G2가 승인한 통합 탐색 가설의 제한된 프로토타입과 검증 결과 |
| 달력 기간 제안 | 착수 후 2일 | 착수 후 최대 21일: 모집 최대 7일, 마지막 최초 과업 후 최대 14일 관찰. 공급 점검 7일은 병행 가능 | 별도 승인 착수 후 최대 14일 |
| 사람 작업시간 상한 제안 | 4시간 | 24시간 | 40시간 |
| 시간 배분 제안 | 설계 2시간, 근거·기록 검토 1시간, 재심 준비 1시간 | 모집 3시간, 고객 과업·정리 6시간, 초기 데이터 3시간, 7일 점검 총 7시간, 후속 관찰 2시간, 분석·재심 3시간 | 범위·수용 기준 4시간, 구현 20시간, 독립 QA 8시간, 운영·사용성 검토 4시간, 재심 4시간 |
| 모델 작업 실행 한도 제안 | 8회 | 12회 | 16회 |
| 외부 신규 현금 한도 | KRW 0 | KRW 0 | KRW 0으로 가능한 범위의 제안. 별도 예산 없이는 유료 배포·모집·구매 불가 |
| 진입 조건 | 사용자 사업 의도와 팀이 선택한 검증 범위로 설계 가능 | 모집 권한·접근 가능한 적합 참가자·선택 범위의 사용 가능한 출처·작업시간 확보를 먼저 확인 | G1 결과와 비용 기록을 심의하여 G2에서 범위·시간·횟수·필요 현금을 다시 확정 |
| 현재 판단 | 수행 가능: 문서·공개 근거 검토 중심 | 조건 미충족: 참가자·출처·일정 미확보 | 보류: 개발 자동 승인 아님 |

표의 고객 수와 데이터 수는 최대 범위이면서 원래 조사 목표다. 목표 미달을 임의로 성공으로 바꾸지 않는다. 공급원 3곳을 확보하지 못하면 그 사실 자체를 결과로 보고한다. 사람 시간이 확보되지 않은 현재, 에이전트 산출물만으로 고객 과업·응답을 대체할 수 없다.

고객 과업 6시간에는 여러 범주의 수동 통합 목록과 기존 탐색 방식으로 같은 과제를 수행하는 비교 및 기록을 포함한다. 특정 행사 검색 서비스의 존재만으로 이벤트 통합 탐색의 가치가 없다고 판단하지 않으며, 반대로 통합의 신규성·수요를 입증됐다고 가정하지도 않는다. 공급원 수는 API 엔드포인트 수가 아니라 원자료 공급 주체를 확인해 집계한다. 같은 상위 공급원의 두 API는 독립 출처 두 곳으로 계산하지 않으며, 확인 전 후보를 확보된 공급원으로 기록하지 않는다.

추천안 A에서는 표본이 프로모션·할인, 응모, 팝업·체험 등 최소 3개 범주를 포함하도록 제안하며, 분류·분배는 조사 계획에서 고정한다. 이는 사용자 강제 조건이 아니다. 브랜드와 범주, 정보 공급원의 다양성은 별개로 기록한다. 범주별 참여 자격·구매 조건·당첨 여부·장소·마감·재이용 조건이 달라 정규화·검수·갱신 비용도 달라질 수 있다. 현재 시간 배분은 그 차이를 실측하지 않은 상한안이며, 30항목의 평균 비용을 모든 이벤트로 일반화하지 않는다. 여러 범주를 확보할 수 없으면 A의 미완료를 기록하고, 팀이 B·C로 변경할 이유와 새 검증 주장을 결정한다. 범위 변경 자체는 허용하지만 좁힌 결과를 원래 다범주 검증 성공으로 표시하지 않는다.

## 모델 실행 한도와 계측 한계

한 번의 실행은 외부 조정자가 한 역할에 작업을 전달하여 결과를 받는 한 번의 턴이다. 최초 위임·재개·반론 요청·재시도 각각을 1회로 센다. 주 에이전트의 제안 또는 의장 심의 작업도 작업 장부에 별도 1회 기록한다. 내부 도구 호출 수나 한 턴 안의 실제 모델 추론 호출 수와는 다르다. **위 횟수 한도는 향후 시작점과 적용 단계를 정한 실험 계획이며, G0 또는 이미 진행한 현재 G1 작성·수정 턴에 소급 적용하지 않는다.** 현재까지의 실행은 별도 과거 실적으로 기록하고 비용 미계측을 유지한다. 향후 실험에서는 명시한 시작 시점 이후의 실패·재시도까지 빠짐없이 집계한다.

- 현재 협업 도구는 토큰·비용 집계를 제공하지 않는다. **토큰 예산과 금액 상한의 강제 집행은 불가능하다.** 위 실행 횟수도 운영자가 기록·중단하는 절차적 제한이며 런타임이 자동 강제하는 기능이 아니다.
- 한도를 채우거나 비용을 알 수 없는 장시간 실행이 나타나면 새 작업 접수를 멈추고 결과·불확실성을 정리한다. 실행 횟수만으로 비용 준수나 절감을 주장하지 않는다.
- 최초 검토 1회, 교차 검토 1회, 통합·재심을 기본으로 편성한다. 단순 표현 개선을 위한 반복 생성은 하지 않는다. 실패한 실행도 횟수와 사용시간에서 제외하지 않는다.
- 이후 하네스가 사용량을 반환하면 입력·출력·캐시 토큰, 모델, 실행 ID, 적용 단가의 출처·확인 날짜를 기록한다. 확인 전에는 추정 가격이나 추정 토큰으로 빈칸을 메우지 않는다.

## 0원 신규 지출 조건에서 가능한 업무와 대체 경로

| 상황 | 실행 가능한 대체 경로 | 해석·중단 조건 |
| --- | --- | --- |
| 고객 접촉 권한 또는 적합 참가자 없음 | 조사 질문·과업 양식·분석 기준까지 완성하고 모집 준비 상태로 종료 | 실제 고객 접촉은 별도 지시 범위에서만 수행. 가상 인터뷰·에이전트 응답을 고객 근거로 쓰지 않음 |
| 허용된 모집을 7일 진행해도 목표 인원 미달 | 실제 확보 인원과 모집 경로를 기록하고 부분 관찰만 보고 | 8명 확보로 표시하지 않음. 유료 모집이나 무단 연락으로 목표를 채우지 않음 |
| 지인·기존 이용자만 모집 가능 | 편의 표본임을 명시하고 이 집단의 탐색 결과만 보고 | 대중 수요·획득 비용의 증거로 일반화하지 않음. 긍정 반응만 골라 결과를 꾸미지 않음 |
| 응답 또는 재요청 지연 | 최초 과업 후 14일까지 관찰하고 마감 시 무응답·관찰 종료를 기록 | 무응답이 사용 의사 없음과 같다고 단정하지 않음. 동시에 자발적 재요청 성공으로도 세지 않음 |
| 사용 가능한 출처·재이용 조건 미확보 | 출처 목록과 접근·이용 조건 확인 기록만 남기고 수동 목록 배포 보류 | 허가 요청이 필요하면 요청 계획까지 작성. 공개 열람 가능성을 재배포 허용으로 간주하지 않음 |
| 일일 점검이 제안 시간 한도를 초과 | 실제 소요와 미점검 범위를 기록하고 공급 검증을 중지·재심 | 중간에 표본을 줄인 결과를 원래 30항목 검증 성공으로 쓰지 않음 |

## 장부와 재심 기준

작업별로 `단계 / 작업 ID / 역할 / 시작·종료 / 사람 실제 작업분 / 실행 횟수 / 완료·실패·대기 / 현금 지출 / 모델 토큰·비용 또는 unknown / 근거 / 미완료 범위`를 기록한다. 달력상 응답 대기와 실제 사람 작업시간을 구분한다. 연락처·인터뷰 원문 같은 개인 자료는 공개 저장소에 넣지 않는다.

기간·시간·실행 횟수 중 하나라도 한도에 도달하면 후속 실행을 자동 확대하지 않는다. 비용 기록과 남은 질문을 의장에게 보내 범위 축소·추가 조사·중단을 재심한다. 외부 신규 지출이 필요한 순간에는 0원안의 한계를 보고하고 다른 편성안으로 분리한다.

고객 재요청만으로 수익 모델·획득 비용·지불 의사를 입증하지 않는다. 기준안 종료 시 고객 문제 관찰, 공급 유지 가능성, 실제 작업량, 미계측 모델 비용을 함께 보고한다. 결과가 긍정적이어도 확대안은 G2의 별도 결정 대상이다.
