# G1 고객 조사·마케팅 계획 v2

작성·공개자료 확인일: 2026-11-17. 입력: [G0 결정 D0 v1](g0-pilot.md). 책임: 고객·마케팅 검토 역할.

변경 사유: 사용자가 행사 관광 검색이 아니라 여러 출처의 다양한 이벤트를 한 번에 찾는 서비스라는 원래 의도를 명확히 했고, 근거에 따른 범위 축소 결정은 팀에 위임했다. 따라서 G0의 서울 주말 행사 중심 축소를 확정 방향으로 보지 않고 아래 세 대안을 재검토한다. 브랜드 프로모션·할인·증정·응모·팝업·체험은 조사할 범주 예시이며 확정된 분류체계가 아니다.

상태: 공식 공개자료 조사와 조사 설계 완료. 참가자 모집, 연락, 인터뷰, 광고, 고객 데이터 수집은 실행하지 않았다. 다음 수치들은 계획·탐색 기준이며 실측 결과가 아니다. 본 문서는 제품 개발 또는 지출 승인 요청을 대신하지 않는다.

## 잠정 지역과 기존 대안

지역을 사업 범위의 제한으로 두지 않는다. 온라인 이벤트와 오프라인 이벤트를 함께 검토하며, 서울은 오프라인 표본을 확보하기 위한 잠정 후보일 뿐이다. 공식 관광 목록은 문화·행사 분야의 부분적 비교 대상이다. 그 존재가 브랜드·혜택 등 여러 범주의 통합 탐색 필요성을 반증하지 않는다. 첫 수동 검증도 최소 2개 범주와 서로 다른 운영 주체의 출처를 포함한다. 서울의 시장 우위, 범주 간 수요의 동일성, 범용 통합 서비스 부재는 모두 미확인이다.

**사실에서 도출한 판단:** 문화·관광 목록과 브랜드 내부 이벤트 목록이 서로 다른 웹 경로에 존재한다. 다만 이것만으로 고객의 분산 탐색 부담이나 통합 수요가 입증되지는 않는다. **남은 가설:** 여러 범주의 이벤트를 찾아 비교하는 사용자는 출처 이동과 대상·기간·구매·회원 조건 확인에 반복적인 수고를 겪는다. 범주를 넘나드는 요구가 없으면 고객군이나 통합 단위를 다시 논의한다. 서울문화포털 계열 API는 같은 원천을 공유할 수 있으므로 URL 수를 독립 공급 수로 세지 않는다. 기존 대안의 필터 부재를 차별점으로 전제하지 않고 실제 고객의 비교·조건 확인 부담을 관찰한다.

## 8명 모집 설계와 screener

모집 경로 후보는 향후 게시 권한을 확보한 이벤트 관심 커뮤니티와 공개 참여 신청이다. 지인 소개는 최대 2명으로 제한하고 관계를 기록한다. 실제로 게시하거나 연락하지 않았으며 모집 접근성도 미확인이다. 연령대나 직업을 대표하는 표본이라고 주장하지 않는다.

사전 안내는 “여러 곳의 이벤트 정보를 찾고 비교하는 과정을 알아보는 45분 조사”로 한다. 할인·시간 절약·신규 서비스 선호를 약속하지 않는다. 다음 질문으로 선별한다.

1. 만 19세 이상인가? 온라인/오프라인 이벤트 탐색 여부와 필요 시 이동 권역은 어디인가? 상세 주소는 받지 않는다.
2. 지난 4주에 이벤트·프로모션·체험 등 정보를 직접 찾아본 횟수와 범주는? 0회는 이번 표본에서 제외하고 이유만 집계한다.
3. 가장 최근에는 언제 무엇을 찾았으며 어떤 도구를 썼는가? 짧은 실제 사례를 받는다. “불편했는가”로 선별하지 않는다.
4. 그 탐색은 실제 참여·혜택 이용, 선택 후 포기, 미선택 중 어떻게 끝났는가?
5. 온라인/오프라인 여부, 기간·위치·회원가입·구매 조건 중 실제로 확인했던 것은 무엇인가? 계정·결제 정보를 받지 않는다.
6. 앞으로 2주 안에 이벤트 정보를 다시 찾을 일이 있는가? 고려한다는 응답만으로 수요가 있다고 보지 않는다.
7. 45분 과업 관찰에 동의하는가? 녹화는 선택 사항이며 동의하지 않아도 메모 방식으로 참여할 수 있다.
8. 이벤트 기획·홍보·관련 서비스 개발 종사자인가? 이번 일반 이용자 표본에서는 제외한다.

목표 배분은 최근 4주에 2개 이상 범주를 탐색한 4명 / 한 범주만 탐색한 4명이다. 전체 표본에 최소 2개 이벤트 범주가 포함되게 하고, 한 범주 이용자가 통합에 관심이 없다는 반증도 수집한다. 각 집단에서 참여·혜택 이용과 미선택·포기 경험을 가능하면 균형 있게 모집한다. 불편을 경험한 사람만 뽑지 않는다. 모집이 안 되면 제외 조건을 조용히 바꾸지 않고 편향과 변경 이유를 기록한다. 참가자 ID P01~P08을 사용하고 연락처는 연구 기록·Git 저장소와 분리한다.

## 비유도 인터뷰와 과업 비교

인터뷰에서는 제품 제안부터 보여주지 않는다. 다음 순서를 사용한다.

- 가장 최근 이벤트를 찾기 시작한 때부터 실제로 무엇을 했는지 순서대로 설명해 달라.
- 처음 어디를 열었고 다음에는 무엇을 확인했는가?
- 어떤 조건 때문에 후보를 남기거나 제외했는가?
- 확인하지 못한 정보가 있었는가? 없었다면 무엇이 충분했는가?
- 최종적으로 무엇을 했으며, 선택하지 않았다면 이유는 무엇인가?
- 같은 상황이 다시 생기면 지금 방법을 그대로 쓸 것인가? 그 이유는 무엇인가?

“이 서비스가 있으면 좋겠는가”, “시간을 절약하고 싶은가”는 핵심 근거로 묻지 않는다. 의향과 관찰 행동을 구분한다.

과업은 본인이 실제 관심을 가진 최소 2개 범주의 후보를 각각 찾아 비교하고 기간·온오프라인 위치·구매/회원/응모 조건·혜택 또는 경험의 근거 링크를 제시하는 것이다. 참여자가 범주 간 비교를 원하지 않으면 강제로 필요를 만들지 않고 별도 과업으로 나누며 그 사실을 기록한다. 답이 없으면 “조건을 만족하는 이벤트 없음”도 허용한다. 각 과업 최대 8분이며 진행자가 중간에 추천하지 않는다. 실제 결제·예약은 하지 않는다.

동일 행사를 두 번째로 찾는 학습 효과를 피하기 위해 실제 가능한 서로 다른 항목을 찾되 같은 범주 조합과 비슷한 조건 복잡도를 가진 과업 A·B를 사전에 만든다. 가능한 후보 수와 제약 수를 비슷하게 맞추고 두 조건에서 접근할 수 있는 이벤트 범위를 기록한다. 과업 난이도가 같은지는 보장할 수 없으므로 결과 한계에 남긴다.

| 배정 | 첫 과업 | 둘째 과업 |
| --- | --- | --- |
| P01·P02 | 기존 방식 A | 수동 목록 B |
| P03·P04 | 수동 목록 A | 기존 방식 B |
| P05·P06 | 기존 방식 B | 수동 목록 A |
| P07·P08 | 수동 목록 B | 기존 방식 A |

배정은 참가자가 확정된 뒤 무작위로 하되 위 네 조합을 2명씩 유지한다. 기존 방식은 평소 도구를 자유롭게 사용한다. 수동 목록은 이용 조건을 확인한 이벤트만 같은 필드·중립적 정렬로 제공하고 원문 링크를 붙인다. 두 방식 모두 원문 확인을 허용한다. 목록에 없던 개인화 정보나 운영자의 실시간 추천은 제공하지 않는다. 비교 완료 전 정답·설명·제품 홍보를 하지 않는다. 본 비교는 수동 목록의 유용성 탐색이며 검색 UI의 우수성 실험이 아니다.

## 관찰 기록과 탐색 판정

다음 열로 참가자별 2행을 작성한다. 원시 연락처·녹화·세션 원문은 커밋하지 않는다.

| 필드 | 기록 규칙 |
| --- | --- |
| participant_id / assignment / task / method | 익명 ID, 배정, 과업 A/B, 기존/목록 |
| constraints / input_revision | 사전에 정한 조건과 사용 목록 버전 |
| started_at / elapsed_seconds / timeout | 시작·종료, 8분 초과 여부 |
| sources_visited / source_switches | 확인한 출처와 이동 횟수. 개인정보가 있는 화면은 제외 |
| candidate_ids / outcome | 후보, 성공·부분 성공·없음·중단 |
| verified_fields / errors / unknowns | 기간·장소/온라인·구매/회원/응모 조건별 원문 확인, 오류와 미확인 분리 |
| observed_behavior / participant_statement | 실제 행동과 발언을 별도 기록 |
| facilitator_intervention / confounders | 도움, 연결 장애, 이미 알고 있던 행사 등 |
| later_request / requested_at / prompted | 재요청 여부·시각·유도 여부 |

성공은 후보가 참가자 조건을 만족하고 필수 정보의 근거가 확인된 경우다. “무료” 추측이나 대상 제한 누락은 시간 단축으로 보상하지 않는다. 조건에 맞는 후보가 없는 과업은 실패로 단정하지 않고 공급 한계로 분리한다. 총시간만 비교하지 않고 성공·오류·미확인 수와 개인별 차이를 함께 본다.

G0의 8명 중 5명 반복 불편, 2주 내 3명 자발적 재요청은 탐색용 기준으로 유지한다. 반복 불편은 최근 사례와 관찰 과업에서 같은 종류의 출처 이동·조건 확인 문제를 구체적으로 보인 경우에만 기록한다. 진행자는 모호한 긍정 발언을 불편으로 재분류하지 않는다. 기준 통과는 다음 조사 심의 사유이며 개발·투자 승인으로 자동 연결하지 않는다.

자발적 재요청은 초기 세션 후 14일 안에 사용자가 먼저 다음 관심 범주/조건의 목록을 요청한 경우다. 모두에게 동일한 요청 방법을 한 번 안내하고, 관찰 기간에는 리마인더·행사 추천·요청 보상을 보내지 않는다. 14일 종료 뒤 비응답 이유를 묻는 후속 조사는 별도로 표시하며 자발적 요청에 포함하지 않는다. 연락 수단은 사전 동의 범위 안에서 마련한다.

2주는 이벤트 주기·개인 일정·계절·조사 참여 효과에 민감하다. 재요청은 지불 의사, 장기 잔존율, 고객 획득 비용의 증거가 아니다. 무응답도 수요 부재로 단정하지 않는다. 실제 동의 고객이 없으므로 현재 지표는 모두 미측정이다.

| M1 목록 | “여러 곳의 이벤트를 한 목록에서 살펴보고 원문으로 확인하는 방식을 시험합니다.” | 목록 형태와 비교 정보가 이해되는가? |
| M2 조건 확인 | “할인·증정·체험 등 관심 이벤트의 참여 조건을 비교하는 과정을 함께 시험합니다.” | 조건 확인이 고객의 실제 문제와 연결되는가? |
| M3 알림 | “관심 분야의 새 이벤트와 마감 정보를 받아보는 방식이 필요한지 조사합니다.” | 반복 탐색보다 알림 방식에 수요가 있는가? |

첫 단계는 8명 과업 종료 후 문구를 무작위 순서로 보여주고 “무엇을 해주는 것으로 이해했는가”, “현재 방식과 무엇이 달라 보이는가”를 묻는다. 선호 순위는 정성 신호로만 사용한다. M3을 보여준 뒤 재요청을 측정하면 기대를 유도할 수 있으므로 재요청 관찰 종료 후 별도 세션/응답으로 받는다. 세 문구는 문장만이 아니라 가치 제안도 다르므로 단순 카피 A/B 테스트로 부르지 않는다.

후속 채널 후보는 이벤트·혜택 관심 커뮤니티 게시와 일반 관심사 커뮤니티 게시다. 게시 규칙·운영자 허가를 먼저 확인하고 권한이 없으면 사용하지 않는다. 별도 모집 예산과 실행 결정 후, 같은 채널 내에서 하나의 메시지만 바꾸고 링크·대상·노출 기간을 고정한다. 채널 간에는 동일한 문구를 사용한다. 두 요인을 동시에 바꾸지 않는다. 각 링크의 노출 가능 수·방문·적격 신청·완료·운영 시간을 구분하고, 노출 수를 알 수 없으면 CTR을 계산하지 않는다. 현재 유료 광고 집행안과 승자 판정 표본 수는 미정이다. 표본·노출 상한을 정하기 전 게시하지 않는다.

## 고객·마케팅 권고

| 대안 | 고객 근거·차별성·조사 가능성 판단 |
| --- | --- |
| A 다양한 범주 통합을 작은 표본으로 검증 | 원래 문제인 범주 간 분산 탐색을 직접 검증할 수 있다. 고객 근거는 아직 없으며 자료·조건의 이질성으로 준비 비용이 높다. |
| B 단일 진입 범주에서 시작 | 조건·공급을 통일하기 쉬우나 어느 범주에 수요가 집중되는지 근거가 없다. 선택 후 다른 범주와의 연결 질문을 남길 수 있다. |
| C 서울 문화행사로 한정 | 공개자료 접근성이 좋고 실험이 쉽다. 원래의 범주 간 통합 가설을 검증하기 어렵고 기존 목록 대비 새로운 가치도 미확인이다. 기존 서비스 존재만으로 기각하지는 않는다. |

**독립 추천: A.** 우선 2개 범주·작은 수동 표본으로 분산 탐색 문제가 실제로 있는지 확인한다. 이는 모든 범주를 즉시 개발하자는 제안이 아니다. 공급·시간 상한을 넘으면 B로 줄이되 그 변경은 실험 범위 축소로 기록하고, 사업을 단일 범주로 전환하는 결정은 고객·운영 결과를 받은 뒤 별도로 심의한다. C는 비교 자료 또는 런타임 기술 실험으로는 가능하지만 현재 고객 가설의 첫 검증으로 추천하지 않는다.

여러 범주의 이벤트 통합 탐색을 사업 가설로 유지하고, 첫 조사도 최소 2개 범주를 유지한다. 서울은 오프라인 자료 표본의 잠정 후보로만 취급한다. 고객 문제가 실제로 관찰되는지, 다른 범주를 함께 볼 필요가 있는지, 이용 가능한 목록과 총예산 상한을 확인해야 한다. 실제 고객 접촉은 별도 실행 권한을 확보한 후 진행하며 합성 참가자로 대체하지 않는다. 고객 반응을 만들기 위해 공급 범위·조건·조사 기준을 사후 변경하지 않는다. 현재 결과는 시장 검증이 아니라 조사 준비 결과다.
