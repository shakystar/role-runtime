# 개발 계획

날짜에 맞춰 기능을 쌓기보다, 각 단계의 가설을 검증한 뒤 다음 범위를 정한다. 스프린트 종료 시 실행 데모, 증거, 결정 변경, 다음 백로그를 남긴다. 문서 작성 완료와 실행 검증 완료를 구분한다.

## Codex 어댑터 분리와 복구

독립 [codex-adapter](https://github.com/shakystar/codex-adapter) 저장소에 Go 구현·언어 독립 JSON CLI·계정 사전 검사를 분리했다. role-runtime은 게시 커밋을 직접 참조한다. 자동 테스트 및 GitHub CI 통과와 별개로, 실제 계정 라우팅 timeout이 재현되어 모델 및 6역할 팀 복구 검증은 진행 중이다. [실험·진단 기록](../experiments/event-search/target-review-team.md)을 따른다.

## Sprint 1 — 재사용 가능성

완료: 합성 모델을 연결한 실제 하네스 기능 검증. LLM 품질·비용·메모리 효율 검증은 아님.

목표: 기존 하네스에서 역할 교체·복원이 가능한지 확인한다.

산출물: 버전/라이선스 표, 두 후보의 최소 실행 실험, 실제로 보장 가능한 어댑터 계약, 채택 ADR.

종료 기준: A → B → A 결과와 역할·도구·상태 격리 증거가 있고, 미지원 항목 및 프로세스 재시작 필요 여부를 설명할 수 있다. 두 후보가 모두 부적합하면 자체 하네스의 최소 필요 범위를 결정한다.

## Sprint 2 — 제한된 실행 코어

목표: 외부에서 지정된 역할을 K개 워커로 실행한다.

산출물: 작업 계약, fake executor, 역할 저장소, 상태 저장, 동시 실행 제한, 선택한 하네스 어댑터.

종료 기준: 역할 40개·K=4에서 실행 수와 격리를 지키고 큐·출력 버퍼가 제한된다. 역할 수만큼 상주 실행 인스턴스를 만들지 않는다.

## 협업 제어 — 최소 구현 완료

[Heartbeat와 역할 메일박스](design/messaging-backlog.md)의 최소 구현: 활성 워커 감시, 영속 메시지, 대기 시 슬롯 반환, 메시지 도착 후 재개. 외부 작업 공급자의 작업 선택 책임은 유지한다.

검증 완료: 네 역할 모두 대기 후 워커 반환, 응답 실행과 재개, 중복 전달, 저장소·pi 재시작, 오래된 실행 결과 거절. [결과](research/cooperation-results.md)에 합성 모델 검증과 실패 주입 범위를 기록했다. 실행 중 장애의 자동 재실행은 지원하지 않는다.

다음 결정 대상은 운영자 복구·대기 timeout·저장소 인덱스와 자원 측정이다. DB 페이징은 별도 후속 검증으로 유지한다.

## Sprint 3 — 자원·비용 검증

합성 자원 검증 완료: 역할 40·100·400개와 워커 1·2·4·8·12개 비교, 전체 프로세스 RSS·CPU·처리량·실행 p95, 예산 기반 워커 추천. [결과](research/resource-results.md)와 [계측 계약](design/resource-sizing.md)을 참고한다. 실제 모델 비용 검증과 운영용 메모리 상한은 아직 남아 있다.

목표: 역할 교체의 이점과 비용을 비교군 B0/B1과 비교한다.

산출물: 재현 가능한 합성 벤치마크, 전체 프로세스 메모리와 지연 보고서, 제한된 실제 모델 실험.

종료 기준: 측정 결과로 가설 유지·수정·기각을 결정한다. 기존 하네스에 비해 이점이 없으면 범위를 재설정한다.

## Sprint 4 — 복구와 기억 구성

목표: 중단·재시도 시 상태를 보존하고 필요한 기억을 선택한다.

산출물: 실패 주입, 중복 처리 정책, 체크포인트 버전 정책, 단순 상태 저장 대비 Letta 등 메모리 계층 비교.

종료 기준: 작업 유실 여부와 부작용 중복 처리 결과를 설명하고, 기억 검색이 작업 정확성과 비용에 미치는 영향을 별도로 측정한다.

## 다음 실제 실험 — 사업 조직에서 제품 실행까지

사용자 방향 변경: 개발 파이프라인에 한정하지 않고, 이벤트·혜택 검색 사업의 제안·임원 심의·예산 편성·마케팅·제품·개발·운영을 전문 역할이 검토한다. 근거에 따라 방향 전환·보류·중단을 허용한다. [조직 실험 계약](../experiments/event-search/README.md)에 40개 역할, 첫 안건, 결정 절차, 단계별 검증을 정의했다. 현재는 설계이며 실제 모델 조직 실행 결과가 아니다.

협업 에이전트로 [G0 제안 심의](../experiments/event-search/g0-pilot.md)와 [G1 조사 준비·범위 재심](../experiments/event-search/g1-decision.md)을 진행했다. 사용자는 원래 목적을 설명하되 범위 선택을 팀에 위임했다. 이후 Welcome to Korea 안건을 실제 Pool로 실행하기 위해 [Codex 어댑터](design/codex-adapter.md)를 구현했다. 제한된 advisory 역할의 실행·재개와 Codex SMS 문서 전달을 검증했다. 전체 조직·쓰기 도구는 미완료다. 400역할 합성 실행 결과를 사업 판단 품질이나 실제 조직 효율의 증거로 쓰지 않는다. 임원 의사결정과 작업 공급은 런타임 외부 계층으로 유지한다. DB 페이징은 계속 후속 범위다.

## Sprint 5 — 실제 작업 MVP

Codex advisory 파일럿: Go app-server 어댑터·역할 thread 영속 매핑을 추가하고 실제 Pool에서 4역할·최대 2워커·7작업 및 재시작 복원 3건을 검증했다. [결과](research/codex-pilot-results.md). 전체 조직 실행, 쓰기 도구와 자원 비교는 남아 있다.

후속 업데이트: [Codex heartbeat·CooperativePool 문서 SMS](research/codex-heartbeat-sms-results.md) 연결과 실제 1워커·3단계·대기/재개 검증을 완료했다. 모델/step의 기본 경과시간 기한을 제거했다. [경주·대구·포항 제안 심의](../experiments/event-search/regional-decision.md)도 실제 실행했다. 큰 문서 참조·Codex SMS 재시작 통합 검증·전체 조직·쓰기 도구·자원 비교는 남아 있다.

[경주 자료 발견 → 검증 → 심의](../experiments/event-search/gyeongju-evidence-pipeline.md)도 실제 Codex로 완료했다. 공식 후보 6곳, 3역할·1워커·5회 실행, 대기·재개 2회와 두 SMS의 생성 내용 반영을 확인했다. 심의는 장소 선택에 필요한 구체적 활동·비용·소요시간의 추가 근거를 요청했다. 웹 수집은 외부 공급자가 수행했으며 자동 SNS 수집·주기적 변경 추적·제품 효용 검증은 남아 있다.

[역할 자체 웹 조사](../experiments/event-search/community-data-pipeline.md) 후속 실행 완료: 검색 권한을 역할별로 적용하고 커뮤니티 조사→데이터 조사→심의를 1워커에서 실행했다. 167.96초, 5 turn, 웹 도구 완료 이벤트 10회, 대기·재개 2회 및 문서 반영 검사 통과. 국내 커뮤니티 수요·경주 실제 행 확보는 미검증이다. 다음은 소량 데이터 검수와 기존 지도 대비 추가 효용 확인이며, 출처 목록을 마지막 심의까지 보존하는 전달 계약도 보완해야 한다.

목표: 사업 검토부터 제품 구현까지 외부에서 지정한 역할 작업을 실행한다. DTO → 컨트롤러 → 픽처 → QA는 제품 개발 단계의 하위 작업열이다.

산출물: CLI 또는 최소 API, 상태 조회, 합성 프로젝트 기반 end-to-end 데모, 운영 문서.

종료 기준: 실행 중단 후에도 프로젝트 작업을 이어가고 결과물의 자동 검증을 통과한다. 작업 자동 분해·웹 UI·분산화는 결과를 보고 다음 백로그로 결정한다.
