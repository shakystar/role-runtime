# 요구사항

## 문제 정의

전문 역할의 수명과 실행 자원의 수명을 분리한다. 수십 개의 전문 컨텍스트를 저장하고, 외부에서 작업이 들어오면 소수의 워커가 해당 컨텍스트로 전환하여 실행한다. 긴 파이프라인의 이전·이후 단계는 상태와 산출물 참조로 보존하고, 현재 실행 가능한 구간만 활성화한다.

## 용어

| 용어 | 의미 |
| --- | --- |
| 역할 정의 | 버전이 있는 전문 지침, 도구 목록, 출력 계약 |
| 역할 상태 | 프로젝트와 역할 인스턴스에 귀속된 기억·결정·재개 정보 |
| 작업 | 외부에서 받은 입력, 역할 참조, 산출물 계약, 식별자 |
| 워커 | 한 시점에 한 실행 컨텍스트를 담당하는 재사용 가능한 실행 슬롯 |
| 하네스 | 모델 호출, 도구 호출, 실행 루프, 이벤트를 제공하는 구성요소 |
| 컨텍스트 | 특정 호출에 실제로 포함된 지침·기억·입력·도구 정의 |
| 체크포인트 | 하네스가 지원하는 안전한 경계에서 저장한 재개 상태 |

워커 수, goroutine 수, OS 프로세스 수, 모델 수는 서로 다르다. pi를 하위 프로세스로 사용하면 그 프로세스의 메모리도 측정한다.

## 초기 범위

- 외부에서 역할과 실행 준비가 된 작업을 지정한다. 작업 우선순위·계획 생성은 하지 않는다.
- 역할과 프로젝트별 상태를 로드하고 안전한 경계에서 저장한다.
- 동시 실행 수 K와 대기열, 컨텍스트 크기, 출력 보관량을 제한한다.
- 작업 및 역할 상태의 소유권을 유지하여 동시 수정 충돌을 막는다.
- A → B → A 전환과 프로세스 재시작 후 복원을 검증한다.
- 최소 한 기존 하네스와 연결하고 기존 방식과 비용·정확성을 비교한다.

초기 범위에 분산 클러스터, 자동 작업 분해, 대시보드, 모델 훈련, KV 캐시 이동은 포함하지 않는다. 장기 기억의 자동 검색·요약은 별도 실험으로 추가한다.

## 수용 기준

| ID | 기준 | 검증 |
| --- | --- | --- |
| R1 | 작업에 지정된 역할·버전을 사용한다 | 실행 이벤트와 컨텍스트 manifest 대조 |
| R2 | 활성 작업 수가 K를 초과하지 않는다 | 동시 실행 계측과 스트레스 테스트 |
| R3 | 다른 역할·프로젝트의 상태를 불러오지 않는다 | 고유 표식, 도구·경로 교체, 로드 참조 검사 |
| R4 | A로 돌아오면 A의 마지막 커밋된 상태를 복원한다 | A → B → A 및 프로세스 재시작 실험 |
| R5 | 작업·역할 수 증가에 따라 활성 메모리가 무제한 증가하지 않는다 | 고정 K에서 전체 프로세스 메모리 추세 측정 |
| R6 | 중단 후 작업 결과와 상태의 불일치를 식별·복구한다 | 저장/도구 호출 경계별 실패 주입 |
| R7 | 모델 컨텍스트 예산을 초과하면 정의된 정책을 적용한다 | 필수 항목 초과는 명시적 실패, 선택 자료는 제외 |

R3의 모델 답변 검사는 보조 증거다. 모델이 표식을 출력하지 않았다는 사실만으로 격리를 입증하지 않는다. 실제 전달된 메시지와 도구 정의, 상태 참조를 검사한다.

## 아직 결정하지 않은 것

- pi 또는 Eino 채택, 하네스 어댑터의 세부 인터페이스.
- SQLite 기반 로컬 저장 여부와 장기 기억 시스템 도입 여부.
- 역할 상태 공유 범위와 같은 역할의 여러 작업을 병렬화하는 정책.
- 프로젝트 라이선스, Go 도구체인 버전, 초기 지원 OS.
- Go + 기존 하네스 대비 자체 하네스가 필요한 구체적인 제약.
