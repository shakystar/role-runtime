# 협업 제어 검증 결과

2026-11-17, Go 1.26.11, Node 24.16.0, pi 1.5.2. 실제 pi RPC에 합성 공급자를 연결했다. 실제 모델의 협업 품질이나 메모리 절감량을 측정한 결과가 아니다.

## 실행 시나리오

외부 공급자가 요청 역할 네 개를 먼저 제출한다. 각 역할은 SMS 요청과 체크포인트를 저장하고 응답 대기로 내려간다. 네 역할이 모두 `waiting`인 것을 확인한 뒤에만 응답 역할 네 개를 제출한다. 응답 역할은 저장된 요청을 읽고 응답을 보내고, 요청 역할은 자기 체크포인트·역할 기록·응답을 복원해 완료한다.

| 조건 | 완료 작업 | 실행 단계 | 대기 / 재개 | 최대 활성 | 생성 pi 프로세스 |
| --- | --- | --- | --- | --- | --- |
| 워커 재사용 | 8 | 16 | 8 / 8 | 4 | 4 |
| 네 요청 역할 대기 후 저장소 재개방·pi 전체 교체 | 8 | 16 | 8 / 8 | 4 | 8 (교체 전후 각각 4) |

초기 race 통합 실행에서 실제 heartbeat 성공 횟수는 각각 84회와 82회였다. 횟수는 스케줄링에 따라 달라지므로 테스트는 모든 단계에서 초기 probe가 수행되고 주기적 probe도 추가로 성공하는지를 확인한다. 재시작 검사는 대기 상태에서 정상 종료 후 복원이다. 실행 중 비정상 중단의 안전성은 별도 저장소 실패 시나리오로 검사한다.

## 실패와 경합 검사

- 네 워커 동시 실행 후 모두 대기해도 활성 실행 수가 0으로 내려가며, 이후 응답 작업이 실행된다.
- 먼저 도착한 응답, 동시 중복 전달, 다른 역할 버전의 메시지를 구분한다.
- outbox 전달 후 정리 전 중단을 재현하고 재시작 시 중복 없이 저장을 마친다.
- 실행 중인 기록을 남기고 저장소를 다시 열면 자동 재실행하지 않고 격리한다.
- 만료된 임대의 갱신·완료, 이전 generation의 결과, 다른 역할을 사칭한 발신을 거절한다.
- 초기 heartbeat 실패, 실행 도중 heartbeat 중단, heartbeat는 정상이지만 작업이 끝나지 않는 경우를 검사한다.
- 기존 pi/Eino 역할 전환과 40역할·4워커 회귀 검사도 유지한다.

실제 역할 간 메시지 전송은 모델 턴 종료 후 구조화된 Transition으로 수행한다. 실행 도중 비동기 메시지 주입과 실제 모델에 대한 검증은 포함하지 않는다. 파일 기록 보존 정책과 대규모 조회 성능도 후속 검증 대상이다.

## 재현

```sh
./scripts/go.sh run ./cmd/role-runtime cooperate-demo
ROLE_RUNTIME_INTEGRATION=1 ./scripts/check.sh
```

`cooperate-demo`는 임시 저장소를 사용하고 종료 시 정리한다. 재시작 시나리오는 `TestRealPiCooperationAfterRestart`에서 실행한다. 계약과 제한은 [협업 실행 설계](../design/cooperation.md)를 따른다.
