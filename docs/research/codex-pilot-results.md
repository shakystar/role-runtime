# 실제 Codex 어댑터 파일럿

2026-11-17, 로컬 Codex 0.166.0, Go 런타임. 공급한 사업 가설은 Welcome to Korea: 공공기관의 국내 여행 정보를 기본 공급으로 삼고 민간 직접 등록·광고로 수익화하는 안이다. 실제 시장 조사 결과를 입력으로 가정하지 않았다.

## 실행 증거

[비식별 실행 지표](codex-pilot-metrics.json)에 상태·Pool 통계·부분 토큰 계측을 기록한다. 모델 출력·입력·thread ID·역할 확인값은 커밋하지 않으며 로컬 ignored artifacts에만 보존한다.

- pilot-01: **7/7 성공, 77.41초**. 고객·재무·운영 독립 검토 3개, 프로세스와 Store 종료·재시작, 같은 역할 교차 검토 3개, 의장 결정 1개. 최대 활성 작업 2개, 프로세스 시작 총 5회(단계별 2+2+1). 같은 프로세스가 서로 다른 역할을 실행했다.
- 역할별 전용 난수는 첫 입력에만 주고 재개 입력 및 타 역할 공유 자료에서 제외했다. 같은 thread ID 및 확인값 복원 **3/3 통과**. 이전 협업 에이전트 회의와 달리 `engine.Pool → codexadapter → codexrpc → 실제 Codex 모델` 경로다.
- pilot-02: MCP 설정 비활성화 및 사용량 보고를 보완한 뒤 두 turn이 120초 deadline에 도달했다. 남은 작업은 SIGINT로 취소했다. active intent가 남고 격리 파일이 기록되었다. 이 실패를 자동 재시도로 덮지 않고 새 state로 분리했다.
- probe-03: 동일 최신 코드의 단일 역할·단일 turn 성공. 이 실행 자체는 역할 복원 증거가 아니다.
- pilot-04: 최종 코드 전체 재검증 **7/7 성공, 67.66초, 재시작 후 역할 복원 3/3**. 최대 활성 작업 2개와 총 프로세스 시작 5회도 유지했다. 따라서 최종 설정에서도 전체 경로를 확인했지만 pilot-02 시간 초과의 원인이 규명된 것은 아니다.

성공 실행과 시간 초과 실행의 세션 메타데이터에서 모델 `gpt-6-astra`, effort `medium`을 확인했다. 모델을 별도로 지정하지 않고 로컬 기본 설정을 사용했다. 실패 실행도 config/read, thread/start와 active intent 저장까지 진행했고 모델 출력·토큰 사용량 알림 이전에 멈췄다. 설정 변경과 시간 초과의 인과관계는 확인하지 못했다. 단일 재검증 성공만으로 일시적 장애라고 단정하지 않는다.

## 사업 심의에서 나온 결론

첫 실행의 의장은 광범위한 운영과 본투자를 보류하고 한 고객군·지역의 여행 준비 과제로 범위를 좁힌 검증을 권고했다. 고객 담당은 공급 방식 자체가 고객 차별성이 아니라고 지적했고, 재무는 범위 축소만으로 광고 수익성이 개선되지 않는다고 반론했다. 운영은 데이터 이용·갱신 및 민간 등록 검수 조건을 요구했다. 이전 이벤트 통합검색안과의 우월성은 미확인으로 남겼다.

이는 모델이 산출한 사업 가설 심의다. 실제 고객·광고주의 수요나 매출을 검증한 것이 아니며, 동일 계열 모델 역할들의 의견 일치는 독립된 시장 증거가 아니다.

최종 pilot-04 의장도 특정 고객의 여행 탐색 과제 하나로 검증 범위를 좁히고 확장을 보류했다. 공공기관 자동 공급·민간 직접 등록 원칙은 유지하되 지역 축소만으로 차별성·수익성이 입증되지 않는다는 반론을 남겼다. 이는 고정된 응답을 재생한 것이 아니라 새 실제 모델 실행에서 얻은 결과다.

## 확인한 것과 남은 것

확인: Go RPC 연결, 제한된 Pool의 실제 모델 실행, 역할별 thread 교체·영속 매핑, 프로세스 재시작 후 역할 복원, 실제 완료 receipt와 의존 단계 공급. fake subprocess 검사에서는 프로토콜 오류·상한·취소·응답 유실·불확실 intent 격리도 검증했다.

미확인: 전체 40역할 조직, 기존 하네스 대비 성능·메모리 우위, 전체 토큰 비용, Codex의 heartbeat/SMS/CooperativePool 연동, 실제 개발용 쓰기 도구, 모델 출력 품질 우위, DB 페이징. 첫 파일럿은 4개 역할·최대 2워커이며 독립 검토와 교차 검토를 단계별로 공급한 실행이다.

`./scripts/check.sh`의 포맷·vet·Go race 검사·Python 검사·pi 합성 공급자 테스트가 통과했다. 실제 모델 호출은 해당 자동 검사에 포함하지 않고 별도 실행했다.
