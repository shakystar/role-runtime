# Sprint 2 — Go RPC와 40역할·4워커

2026-11-17 로컬 macOS, Go 1.26.11, Node 24.16.0, pi 1.5.2에서 검증했다. 실제 pi 프로세스와 도구 루프를 사용하되 모델 응답은 합성 공급자다. 외부 모델 호출은 없다.

## 결과

| 모드 | 역할 | 워커 | 작업 | 성공 | 최대 활성 | 최대 대기 | 생성 프로세스 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 프로세스 재사용 | 40 | 4 | 80 | 80 | 4 | 8 | 4 |
| 작업별 새 프로세스 | 40 | 4 | 80 | 80 | 4 | 8 | 80 |

초기 실행에서 각 워커는 서로 다른 역할 10개를 처리했다. race 검사를 켠 재검증에서도 두 모드 모두 80개 작업이 성공했고, 재사용 워커별 역할 수는 18/10/10/17개였다. 역할은 특정 워커에 고정되지 않는다. 모델 경계에서 역할 지침, 도구 allowlist, 프로젝트 경로, 이전 라운드 기록과 다른 역할 기록의 부재를 검사했다. 두 모드 모두 동일한 작업과 합성 도구를 실행했다.

초기 실행 시간은 재사용 21.60초, 새 프로세스 15.23초였다. 단일 실행이며 저장소 fsync와 초기화 등의 영향을 분리하지 않았다. 속도 우위나 메모리 절감의 근거로 사용하지 않는다. 비교군은 작업마다 새 프로세스를 만드는 방식이며, 다른 기존 워커 풀 전체와의 비교가 아니다.

## 구현과 검사

- 제한된 Go 작업 큐와 워커 풀. 같은 프로젝트·역할·버전·인스턴스는 동시에 실행하지 않는다.
- 불변 역할/프로젝트 정의, 작업 ID 중복 방지, 파일 기반 실행 기록, 단일 소유자 잠금.
- RPC 응답 ID 상관관계, 시작 승인과 최종 완료 구분, 취소·중단·비정상 종료, 출력 크기 제한.
- pi 세션 전환 후 ID/경로 확인, 활성화마다 역할 지침과 도구 목록 구성.
- 불확실하게 종료된 세션은 격리하여 자동 재사용을 거절한다.

`./scripts/check.sh`는 Go 포맷·vet·race 테스트와 기존 pi/Eino 회귀 검사를 수행한다. 실제 40/4 통합 검사는 별도로 실행한다:

```sh
./scripts/go.sh test -race -tags integration -count=1 -v ./internal/pispike
```

초기 fake executor 테스트는 400개 작업에 10초 제한을 두어 실패했다. 파일마다 동기화하는 저장소 비용을 고려해 수용 시나리오인 80개 작업과 1분 제한으로 조정했다. 이는 처리량 개선을 의미하지 않는다.

## 한계와 다음 단계

현재 CLI는 합성 데모다. 임의 실제 모델을 이용하는 제품 API, 영속 스케줄러, 장애 후 자동 재실행, heartbeat, 역할 SMS, 대기/재개는 아직 없다. 세션 파일 형식은 pi v3에 결합되어 있으며 버전 변경 시 재검증해야 한다.

저장소는 macOS/Linux 단일 프로세스 소유 방식이다. 작업 접수 기록은 영속적이지만 메모리 큐의 자동 복구는 없다. 재시작 후 미완료 기록은 명시적인 복구가 필요하다. 역할 도구 제한은 OS 보안 경계가 아니고, 프로세스 그룹 종료도 그룹을 이탈한 자식 프로세스까지 보장하지 않는다.

컨텍스트는 현재 pi 기록 복원이며, 16MiB 세션 파일 제한을 넘으면 거절한다. DB 페이징이나 모델 컨텍스트 확대를 구현한 것이 아니다. 다음은 [협업 제어](../design/messaging-backlog.md), 이후 [페이징 검증](../design/paging-backlog.md)이다.
