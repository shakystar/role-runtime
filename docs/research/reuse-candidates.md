# 재사용 후보 조사

조사일: 2026-11-17. **문서 기반 예비 조사이며 소스 실험이나 성능 검증 결과가 아니다.** 후보 버전·커밋과 라이선스 원문 검토는 첫 스프린트에서 완료한다. 아래 링크는 변경 가능한 upstream 문서다.

## 후보별 경계

| 후보 | 문서에서 확인한 것 | 재사용 후보 범위 | 아직 확인할 것 |
| --- | --- | --- | --- |
| pi | 장기 실행 프로세스를 JSONL RPC로 제어, TypeScript SDK 제공 | 모델 연결·도구 실행·에이전트 루프 | 동일 프로세스의 역할·세션·도구·cwd 교체와 완전한 해제 |
| Eino | Go 기반 Agent/Runner, 이벤트, checkpoint/resume | Go 내부 실행기와 복구 기능 | 역할별 격리, 중단 경계, 스냅샷 크기·참조 수명 |
| MemGPT / Letta | 가상 컨텍스트 관리와 영속적인 에이전트 기억 | 기억 선택·보존·검색 | 독립 메모리 계층으로 사용할 때의 결합도와 운영 비용 |

공식 근거:

- [pi RPC](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md): 언어 독립적 subprocess 제어 경로. 이전 badlogic/pi-mono URL은 이 저장소로 연결된다.
- [Eino 개요](https://www.cloudwego.io/docs/eino/core_modules/eino_adk/agent_preview/)와 [Runner](https://www.cloudwego.io/docs/eino/core_modules/eino_adk/agent_extension/): 실행·이벤트·복구 인터페이스.
- [MemGPT 논문](https://arxiv.org/abs/2310.08560): 제한된 컨텍스트와 외부 저장소 사이의 계층적 기억 관리.
- [Letta 상태 관리](https://docs.letta.com/v1-sdk/concepts/stateful-agents)와 [저장소](https://github.com/letta-ai/letta): 상태·기억 영속화. API 세대 차이를 확인할 필요가 있다.

## 실험 질문

### pi

- 한 프로세스에서 A → B → A 전환이 가능한가? 어떤 명령 또는 확장이 필요한가?
- 시스템 지침, 메시지, 도구 목록, 확장 상태, 작업 디렉터리 중 무엇을 교체할 수 있는가?
- 프롬프트 수락 이벤트와 실제 실행 완료를 어떻게 구분하는가?
- 취소 후 실행 중인 도구와 하위 프로세스가 남는가?
- 세션 변경 후 이전 상태가 메모리에 계속 참조되는가?
- SDK 래퍼가 필요하면 작은 어댑터로 충분한가, 포크가 필요한가?

### Eino

- Go 내부에서 역할 정의와 입력 상태를 실행마다 분리할 수 있는가?
- checkpoint가 어떤 데이터를 보관하며 어떤 타입·버전 제약을 갖는가?
- 취소와 재개가 모델 호출·도구 실행의 어느 경계까지 보장되는가?
- 워커 반환 후 goroutine과 상태 참조가 해제되는가?
- 우리 작업 입력 계약을 유지하면서 필요한 실행 기능만 사용할 수 있는가?

### MemGPT / Letta

- 역할 기억과 프로젝트 기억을 구분하고 필요한 자료만 조회할 수 있는가?
- 실행 상태와 장기 기억 저장의 책임이 중복되는가?
- 외부 서비스로 사용하거나 일부 구성요소를 재사용하는 비용은 무엇인가?
- 단순한 상태 저장소 대비 회수 정확도, 지연, 토큰 사용량에 이점이 있는가?

메모리 실험은 실행기 선택과 분리한다. 초기 A → B → A 실험은 정해진 기억 참조로 시작해 자동 검색의 오차를 섞지 않는다.

## 채택 기록 양식

각 후보에 대해 다음 항목을 채운 뒤 ADR을 갱신한다.

| 항목 | 기록할 내용 |
| --- | --- |
| 버전 | release와 commit SHA, 실행 환경 |
| 라이선스 | 해당 버전의 원문 URL, SPDX 식별자, 재배포/고지 조건 |
| 사용 경계 | RPC, SDK, 외부 서비스, 소스 복사 또는 포크 여부 |
| 실행 결과 | 명령, 합성 입력, 로그·측정 파일 위치, 재현 방법 |
| 미지원 기능 | 역할 교체, 상태 복원, 취소 등에 대한 제한 |
| 운영 비용 | 프로세스 수, 의존성, 업그레이드·호환성 부담 |
| 결론 | 채택/보류/탈락 및 근거, 대체 경로 |

처음부터 포크하지 않는다. 공개 확장 지점으로 해결 가능한지 먼저 검증하고, 포크가 필요하면 이유와 유지 비용을 별도 결정으로 남긴다.
