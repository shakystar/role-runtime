# ADR 0002 — 첫 실행 어댑터로 pi RPC 사용

- 상태: Sprint 2 구현 방향 채택. 운영 적합성·성능은 후속 검증 대상.
- 근거: [Sprint 1 실험 결과](../research/sprint-1-results.md).

## 결정

Go는 작업 접수, 실행 슬롯, 상태 참조, 역할 버전과 예산을 관리한다. 첫 실행 백엔드는 pi 1.5.2의 RPC와 작은 역할 확장으로 구성한다. 활성 워커마다 pi 프로세스 하나를 두고, 역할마다 프로세스를 생성하지 않는다. 첫 구현에서 pi를 포크하지 않는다.

Eino v0.9.23도 같은 기능 fixture를 통과했으므로 비교군 및 대체 후보로 보존한다. 자체 하네스 전체 재작성은 필요하다고 결론 내리지 않았다. Letta는 별도 메모리 실험까지 도입을 보류한다.

## 선택 이유

- 실제 RPC에서 같은 프로세스의 역할·지침·도구·프로젝트 경로 교체를 확인했다.
- 완료된 대화의 세션 저장·복원을 기존 하네스가 제공한다.
- 코딩 도구와 실행 루프를 재사용하는 방향이 초기 사용 사례와 맞는다. 실제 코딩 도구의 품질·격리는 다음 실험에서 확인해야 한다.
- Go 제어 계층과 하네스를 프로세스 경계로 분리해 백엔드 변경 가능성을 유지한다.

Eino는 단일 Go 프로세스에 통합할 수 있지만, 이번 실험에서는 완료 transcript 저장과 경로에 묶인 도구를 직접 구성했다. Go 내부 실행이 중요해지거나 pi 메모리·전환 비용이 불리하면 Eino를 재평가한다.

## 최소 어댑터 계약 초안

| 연산 | 의미 | 반드시 확인할 것 |
| --- | --- | --- |
| Activate | 프로젝트, 역할 ID·버전, 저장된 세션 참조를 로드 | 이전 실행 종료, 역할 정의 검증, 도구 allowlist, cwd |
| Execute | 외부 지정 작업을 한 turn 실행 | 입력 수락과 완료를 구별, 제한된 이벤트 버퍼 |
| Snapshot | 완료 경계의 세션·역할 상태 참조 반환 | 저장 완료와 재개 가능 여부 |
| CancelAndWait | 실행 취소 후 종료 확인 | 취소 수락만으로 슬롯을 반환하지 않음 |
| Release | 활성 세션의 실행 자원 반환 | 리스너·하위 프로세스·참조 수명 |

이는 인터페이스 설계이며 생산용 Go 구현은 아직 없다. 임의의 도구 실행 중간에서 중단·재개할 수 있다고 가정하지 않는다. 체크포인트는 하네스 종류와 버전이 있는 opaque 참조로 취급하고 다른 하네스에 그대로 주입하지 않는다.

## 알려진 비용과 제한

- Node 프로세스가 필요하며 전체 프로세스 메모리에 포함해야 한다.
- `defaultTools`만으로 확장 도구를 격리할 수 없다. 역할 활성화 시 명시적으로 제한한다.
- 세션 재개는 전체 대화 기록 복원에 가깝다. 필요한 기억만 선택하는 컨텍스트 조립·페이징은 별도 작업이다.
- 완료 상태 복원과 실행 도중 장애 복구는 다르다. 후자는 검증되지 않았다.
- 현재 역할 확장의 합성 입력은 신뢰된다. 제품에서는 외부의 역할·세션·경로 참조를 검증하고, 프로젝트 필수 규칙을 지침에 포함해야 한다.
- 역할 전환은 OS 보안 샌드박스가 아니다.

## 재검토 조건

K를 고정해도 pi 메모리가 지속적으로 증가하거나, 취소 후 자원이 회수되지 않거나, 기존 B1 제한 실행보다 이점이 없다면 워커 정책과 백엔드를 재검토한다. 라이브러리 버전 변경으로 세션·확장 계약이 달라져도 동일 fixture부터 재검증한다.
