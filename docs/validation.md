# 검증 계획

현재 측정 결과 없음. 아래 숫자는 실험 입력과 초기 수용 기준이며 실측 성능이 아니다.

## 비교군

| 구분 | 구성 | 확인 목적 |
| --- | --- | --- |
| B0 | 역할마다 하네스 프로세스 상주 | 상주 방식 대비 자원 차이 |
| B1 | 기존 하네스 그대로 동시 실행 K 제한, 작업별 세션/프로세스 사용 | 단순한 제한만으로 얻는 효과 |
| C | role-runtime이 K개 워커에서 역할·상태 교체 | 새 계층의 추가 가치와 전환 비용 |

B0만 이기고 B1 대비 이점이 없다면 메모리 효율을 차별점으로 확정하지 않는다. 복원·격리·운영 편의의 가치가 있는지 별도로 판단한다.

## 실험 순서

1. 결정적 fake executor로 작업 상태 전이와 자원 제한을 검증한다.
2. 실제 하네스로 A → B → A를 수행하고 전달된 컨텍스트와 복원 결과를 검사한다.
3. 역할 수 4/40/400, 단계 수 100/1,000/10,000, K=1/4 조합을 합성 작업으로 측정한다.
4. 선택한 작은 사례만 실제 LLM으로 실행해 정확성·토큰·지연을 비교한다.
5. 저장과 도구 실행 경계에서 실패를 주입하고 재개·중복 처리를 검증한다.

모델, 하네스 버전, 입력, 도구, 머신, K를 비교군 사이에 동일하게 유지한다. 실제 LLM 실험의 모델과 비용 상한은 실행 전에 기록한다. 비교군 실행 순서를 바꾸고 각 조건을 최소 5회 반복한다.

## 측정 항목

- 전체 프로세스 트리의 메모리와 피크 RSS. RSS 합산의 공유 페이지 중복 가능성을 명시하고 플랫폼이 지원하면 PSS도 기록.
- Go heap, goroutine, 파일 디스크립터, 하네스·도구 하위 프로세스 수.
- 활성 작업 수, 대기열 크기, 보관 중인 컨텍스트와 출력 버퍼 크기.
- 역할 로드·해제·복원 시간, 작업 전체 지연의 p50/p95, 처리량.
- 입력/출력 토큰과 제공자가 보고하는 캐시 토큰, 실제 과금 또는 추정 방식.
- 역할·프로젝트 격리 위반, 복원 오류, 누락·중복 작업, 작업 성공률.
- 영속 저장량과 쓰기 비용. 저장 공간 증가를 RAM 절감으로 숨기지 않음.

Go heap 감소, OS RSS 감소, 모델 컨텍스트 토큰 감소는 각각 보고한다.

## 기능 통과 조건

- K 제한 위반, 잘못된 역할·상태 로드, 합성 데이터 복원 오류: 0건.
- A → B → A에서 A의 커밋된 상태 복원, B가 받은 payload에 A 전용 표식·도구 없음.
- 동일 역할의 다른 프로젝트 상태가 분리됨.
- 취소 완료 후 실행이 남아 슬롯을 초과하지 않음.
- 재시작 후 모든 접수 작업이 완료·실패·재개 대기 중 하나로 설명 가능함.
- 외부 부작용 중복 가능성과 복구 절차를 로그로 설명 가능함.

## 자원 가설의 판정

입력·컨텍스트 크기와 K를 고정한 상태에서 역할 수·단계 수에 따른 메모리 추세를 그린다. warm-up과 캐시를 분리하고 긴 실행의 plateau 여부와 반복 실행 분산을 기록한다.

허용 메모리 상한과 전환 지연 예산은 파일럿의 절대값을 확인한 뒤 본 실험 전에 기록한다. 결과를 본 뒤 유리하게 기준을 바꾸지 않는다. 처음부터 특정 절감률을 약속하지 않는다.

메모리가 계속 증가하거나 기존 B1보다 정확도·비용·지연이 악화되면 원인을 분석한 후 설계를 수정한다. 더 복잡한 페이징·검색을 추가하기 전에 단순한 전환 구조부터 재검증한다.
