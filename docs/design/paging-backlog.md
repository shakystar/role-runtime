# 후속 컨텍스트 페이징 요구

사용자가 지정한 순서: **Go RPC 어댑터 → 역할 40개·워커 4개 검증 → DB 기반 컨텍스트 페이징**. 이번 Sprint 2에는 페이징 구현을 포함하지 않는다.

후속 실험에서 보존할 요구:

- 모델 컨텍스트의 2~10배에 해당하는 작업 기억을 DB에 원문으로 보관.
- 16K·64K **토큰** 페이지를 비교 후보로 사용. 확정 크기가 아니며 작은 페이지도 비교 가능.
- 필요한 페이지만 활성 컨텍스트에 올리고 나머지는 ID·버전·요약·위치 인덱스로 참조.
- 목표·필수 규칙·진행 상태는 고정 영역으로 유지.
- 단순 LRU를 기준선으로 측정하고 중요도·의존성을 고려하는 교체 정책과 비교.
- 내려간 자료를 다시 찾는 경로, 페이지 적중률, 재로딩 토큰 비용, 작업 정확성, 지연을 측정.

확장되는 것은 여러 모델 호출에 걸쳐 접근 가능한 기억이다. 한 호출의 attention/context 한도나 KV 캐시를 늘린다고 표현하지 않는다. 역할·프로젝트 상태 격리와 페이지 예산은 별도로 검증한다.

Sprint 2의 `Resolver`는 작업에서 활성화할 역할·프로젝트·세션 참조를 구성하는 경계다. 현재 구현은 파일 기반 정의와 pi 전체 세션을 사용한다. 후속 페이지 관리자는 이 경계를 확장하되 역할 상태 저장과 모델별 토큰 계산 정책을 명시해야 한다.
